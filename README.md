# 乾隆大藏經及永樂北藏

從 suttaworld 下載後，先用 convertzz 轉為 utf8。

全專案用 TypeScript 撰寫，以 [bun](https://bun.sh) 直接執行（不需編譯）。

```
bun run convert:qianlong   # 乾隆藏 → qianlong/ 與 qianlong-fixed/
bun run verify:qianlong    # 驗證轉換沒有增刪文字
bun run convert:ylbz       # 永樂北藏 → ylbz/
bun run verify:ylbz        # 驗證北藏每個經檔的卷數
bun run typecheck          # tsc --noEmit（需先 bun install 取得 @types/node 與 tsc）
```

## 檔案

| 路徑 | 內容 |
| --- | --- |
| `gen-qianlong.ts` / `gen-ylbz.ts` | 兩藏的轉換命令列 |
| `lib/qianlong.ts` | 龍藏 HTML → 文字的純函式（`htmlToPage`、`repair`） |
| `lib/ylbz.ts` | 北藏 HTML → 文字的純函式（`tidyYlbz`） |
| `lib/html.ts` | `stripTags`：去標籤，並救回被吃進屬性的正文 |
| `lib/fsx.ts` | 走檔、讀檔（UTF-8/UTF-16LE）、內容沒變就不覆寫 |
| `lib/text.ts` | 實體解碼、字典序比較、漢字碼位判斷 |
| `verify-qianlong.ts` / `verify-ylbz.ts` | 驗證 |
| `pdf-pages.ts` / `ocr-seg.py` / `ocr-pages.ps1` / `ocr-compare.ts` / `ocr-merge.ts` | 掃描 PDF 拆頁、切行、OCR、與純文本比對（見下） |
| `gridfit.py` / `pdf-cuts.py` / `go/pdfcuts/main.go` | **切圖**：乾隆藏 PDF 的格線偵測與「切成一折」，Python 版與 Go 版（見 [`foldcrop.md`](foldcrop.md)） |
| `yb-frame.py` / `yb-batch.ts` / `yb-verify.py` | **切圖**：永樂北藏掃描圖的三折裁切、批次、驗收（見 [`foldcrop.md`](foldcrop.md)） |

| `qlz-cutcheck.py` | 拿 `qianlongzang/<卷>.zip` 解出來的頁面試跑一次 `pdf-cuts.py`（切折圖那條線的連通性檢查） |

| `raw/ylbz_tripitaka/` | 永樂北藏：4338 個 `.htm` |

龍藏的 `.doc` 是 UTF-16LE 的 Word 97 檔，內容與 `.htm` 重複（含同樣的殘碼），且本機沒有 Word / LibreOffice 可解析，因此轉換只取 `.htm`。

## 乾隆藏輸出

* `qianlong/`：忠實轉換。一個 `.htm` 一個 `.txt`，目錄結構與 `raw/chiarnlurng_tripitaka/` 完全對應。
* `qianlong-fixed/`：同上，另把來源轉換失敗殘留的 4 位十六進位碼還原成 Unicode 字元（2952 處、193 個相異字），對照表見 `qianlong-fixed/_repair-map.tsv`。
* `qianlong/_manifest.tsv`：逐檔清單（`path`、`title`、`chars`、`lines`、`paragraphs`）。
  `lines` 是輸出的實體行數（含空行），`paragraphs` 是來源 Word 段落數，兩者都不是頁數。

轉換規則：

* **原書換行只由 `<br>` 決定**：一個 `<br>` 對一個換行。此為本藏最珍貴的資訊，完全不重排。
  已用 `pdf/第1部 大般若波罗蜜多经 卷01（天）.pdf` 的第 3、4、5 影像逐行核對：
  輸出的每一行都與木刻版的一行（每葉 10 行）完全對應，連續 30 行無誤。
* `<p>` 區塊（Word 段落，每塊約 13 行）→ 前後各留一個空行。**它不是原書頁界**，
  只是保留來源 Word 的段落切分。
* `<hr>` 是導覽列與頁尾的分隔，只用來切出內文範圍，本身不輸出。
* 表格：`</tr>` → 換行、`</td>` → Tab（目錄與選單頁靠此保留欄位對齊）。
* 原始 HTML 的換行與縮排只是排版空白，一律折疊，不當成斷行（已驗證全庫沒有「兩個漢字之間夾一個原始換行」的情形）。
* 已移除 `<head>`／`<style>`／`<script>`／註解／base64 圖片、導覽字（回目錄、上一頁、下一頁、Top、勘誤表）與 crawler 的 `block1` 圖層。

## 掃描卷 → 一卷一個 zip（`qianlongzang/`）

切折圖的前置：把 `full-pdf/`（乾隆大藏經掃描 PDF，3608 檔、33.1 GB）拆成
`qianlongzang/<經號 4 位>-<卷號 3 位>.zip`，一卷一個 zip，內容是原 PDF 內嵌的 JPEG 原圖
（**零轉檔**，位元組與掃描檔相同），zip 一律 store 模式（不壓縮）。3557 卷、173200 頁、31.6 GB。

前綴是**乾隆藏經號**（`full-pdf/` 資料夾名 `第N部` 的 N，已用 `乾隆藏.csv` 全表驗證
1669 筆「編號去掉別本後綴 ＝ 經號」無一例外），**不是**永樂北藏編號——後者在 `yb-out/`。
詳細涵蓋範圍、13 個「一個 PDF 裝好幾卷」的經號、缺件與丟掉的重複檔見
[`qianlongzang/_report.md`](qianlongzang/_report.md)。

```
python qlz-batch.py --jobs=6    # 產生 zip（可續跑，已存在的跳過）
python qlz-verify.py --deep     # 驗收：命名、store、頁序、逐頁位元組與來源相同
python qlz-report.py            # 重寫 qianlongzang/_report.md
```

## 驗證

`bun run verify:qianlong` 目前的結果：

```
filename mapping            1:1 OK
char-exact match            2183/2183  OK
malformed tags (indep.)     19 tags / 86 cjk inside quotes in 1 file(s)
residues in faithful        2952
residues left in fixed      0
repair map total            2952  = faithful residues  OK
```

`char-exact match` 是獨立重走一次「來源 → 文字」（把內文區的標籤換掉、解實體、去掉所有空白）
再與輸出逐字比對，所以空白、斷行、段落怎麼處理都不影響這個檢查；
2183/2183 代表轉換沒有增刪任何文字。

## 頁碼

HTML 正文裡**沒有任何印本頁碼**（掃描全庫 2183 檔，找不到 `第 N 頁`、頁碼獨立成行等痕跡）；
檔名與資料夾名帶的是冊次與經號，例如 `42-48_372-537`＝冊 42-48、經號 372-537，
`001-16_1-19`＝冊 1-16、經號 1-19。

不過**行就是頁的單位**：`pdf/` 的掃描影像每葉固定 10 行，而輸出的行與木刻版逐行對應，
所以「每 10 行＝一葉」可以直接從行結構還原；掃描影像的版心另有原書的千字文頁碼
（例：卷01 第 5 影像中央的「天一」＝天字函第 1 葉），但那只在圖上，PDF 文字層只有 1..40 的流水號。

## 切圖

切圖（把掃描頁切成「一折」）有兩條互相獨立的管線，**演算法、守門條件、批次與驗收
全部在 [`foldcrop.md`](foldcrop.md)**：

| | 乾隆藏（PDF） | 永樂北藏（掃描圖） |
| --- | --- | --- |
| 來源 | `full-pdf/`（3608 檔、33GB） | `yonglebeizang/` 的掃描 JPG |
| 版面 | 一頁 10 行 × 17 字 → **2 折** | 一圖 **3 折**，每折 5 欄 × 17 字 |
| 核心 | `pdf-cuts.py`＋`gridfit.py`（Go `go/pdfcuts`） | `yb-frame.py` |
| 批次 | `batch-cuts.ts`＋`check-batch.ts` | `yb-batch.ts`＋`yb-verify.py` |
| 輸出 | `cuts/`、`full-grid/` | `ylz-image/<經號>-<卷號>.zip`＋`ylz-crop-pos/` |

**`ylz-image/` 目前有 6251 卷、602,958 折**（永樂北藏原掃描 3804 卷 ＋ 乾隆藏補漏 2447 卷），
`yb-verify.py` 全部合格；逐卷來源見 `ylz-image.csv`（詳見 [`ylz-image-report.md`](ylz-image-report.md)）。

`ylz-image/` 是**兩條管線合流的完整全藏**：永樂北藏原掃描（彩圖三折）＋
從乾隆藏補來的缺卷（`yonglebeizang-fill/`，黑白二折，走 `pdf-cuts.py`）。
每一卷的來源記在 `ylz-image.csv`。舊目錄 `yb-out-prefix`／`yb-csv-prefix`
保留為來源備份。

共同的輸出規格：一律 **500 × 1105**（一格 100 × 65，所以 `(x // 100, y // 65)`
就是「第幾欄第幾字」——指定這個尺寸的唯一目的）；折圖依閱讀順序命名 `001.jpg`、`002.jpg`…；
版框的上／下緣橫線要塗白，否則 OCR 會讀成「一」。

## 掃描影像 OCR 與純文本的比對

```
bun run pdf-pages.ts "pdf/第1部 大般若波罗蜜多经 卷01（天）.pdf" ocr/pages
python ocr-seg.py                       # 切行：ocr/rows/*.png（橫排）＋ ocr/cols/*.png（直排，OCR 用）
powershell -NoProfile -ExecutionPolicy Bypass -File ocr-pages.ps1 -Pattern "*.png" -Dir ocr/cols -Out ocr/cols-txt
bun run ocr-compare.ts qianlong/001-16_1-19/1_1-200/220-001.txt
```

整頁直接 OCR 不行：引擎會把相鄰的欄混在一起，行數也對不上（10 欄常常只認出 5–9 行）。
改成先切行再逐行 OCR：

* **切行靠刻本格線，不靠找白隙**。紙張有雜點、行間有滲墨，用「找空白間隙」會把好幾行併成一行；
  但每葉固定 10 行的行距訊號很強（comb 擬合的對比 10–19）。文字區高度若約等於 10 個行距，
  就直接用 10 行均分文字區，**每一頁都是 10 行**（卷題、譯者這種墨少的行才不會被濾掉）。
  行序：整頁逆時針轉 90 度後由上到下＝原書由右到左的閱讀順序，每一行由左到右讀。
* **格線要從影像裡拿掉**。刻本的版框與摺線會被 OCR 讀成「一」——原本 98% 的行首或行尾都多一個「一」。
  分三層處理：(1) 二值化後把「連續 120px 以上的長線」判定為格線（先用 4px 膨脹接起掃描傾斜造成的斷點）；
  (2) 切行與取墨跡範圍都用去線後的遮罩；(3) 裁圖仍取原始灰階（塗白會誤刪「一一」這種連續橫畫），
  最後再把欄圖裡「橫貫整欄」的列塗白（一個字的橫畫最多只占全欄寬約 40%，用 50% 當門檻很安全）。
  現在行首行尾多出「一」的比例降到 21%，欄圖裡的橫條數是 0。
* **只留漢字**。掃描是刻本，不會有 ASCII 也不會有標點；`ocr-pages.ps1` 把 BMP 漢字範圍以外的字元全部濾掉。
  已確認正文本沒有任何非 BMP 字元，所以這個濾網不會誤刪。
* **OCR 要餵直排欄，不要餵橫排**。Windows OCR 讀直排中文很順，餵橫排的單行圖（2334×202）
  會直接回 0 行；餵未旋轉的直排欄（181×1287、原始灰階、四周補白）就正常。
  另外 `ocr-pages.ps1` 必須保持純 ASCII——PS 5.1 把無 BOM 的 .ps1 當 ANSI 讀，
  中文註解會把下一行吃掉，症狀是每個檔都辨識出 0 行。

`ocr-compare.ts` 把逐欄 OCR 與純文本逐行對位（L01 = 閱讀順序第一行），結果：

| 項目 | 結果 |
| --- | --- |
| 每頁行數 | 10（p02–p41 共 40 頁 × 10 = 400 行；p01 是空白封面） |
| 行距 | 35 段裡 31 段剛好 10 行 |
| 逐字命中率（期望字有出現在該行 OCR） | 0.453（2772/6124） |
| 辨識出的行 | 400 行中 296 行有字，104 行引擎沒吐出任何字（該列影像有墨，但引擎放棄） |
| 行首行尾多出的「一」 | 21%（修格線前是 98%） |

`ocr/ocr-merged.txt` 是合併後的完整結果（每頁固定 10 行，沒辨識出字的留空行）。

錯誤型態：漏字（引擎偶爾整行吐不出來，或一行少 1–3 字）、形近代換（說→訧、臾→史、念→拧、種→粒）。

結論：版面已經抓對（**每頁 10 行、順序正確、每行約 17 格**），字大約對一半——
足以定位與校對，但**不能**取代 `qianlong/` 的文字（那份已驗證與來源逐字相同）。



## 來源缺陷

### 1. 4 位十六進位殘碼

來源站 Big5→Unicode 轉換失敗時，把原字的 Unicode 碼位直接留在文字裡
（例：`兩膝兩43F6兩股`、`慈雲4543覆`）。該碼就是原字：`43F6`＝䏶、`4543`＝䕃、`4421`＝䐡、
`3CB2`＝㲲、`3CAA`＝㲪、`356E`＝㕮（㕮咀）……經上下文逐一核對後可完全還原，已套用在 `qianlong-fixed/`。

全庫 2952 處、193 個相異字；`qianlong-fixed/_repair-map.tsv` 列出每個字的次數與上下文。
另外有 26 處刻意不動——那些其實是真數字，只是數值剛好落在漢字碼位
（例如 `599函5940卷`、`718函7168卷` 的卷數統計，`5940` 會變成「奄」、`7168` 會變成「熠」）。

### 2. `@` + 4 位十六進位（未解）

例：`@4782` 961 次、`@1025` 214 次，全庫 3323 處、334 種，多出現在密教咒語的罕用字位置。
其數值不是可直接對應的碼位，且 `.doc` 原檔裡也是同樣的 `@xxxx` 記號，故無法從現有資料還原，
兩種輸出都原樣保留。

### 3. 屬性值沒收尾，吃掉正文（已救回）

少數頁面產 HTML 時漏掉 `">`，正文黏進了 style 屬性：

```html
<span lang="EN-US" style="font-size: 13.5pt;  拘舍<br>羅是菩薩法當念般若波羅蜜…
```

照一般做法整段丟掉的話，《菩薩受齋經》（`067_1077-1101/1100.htm`）十戒的第一～七條會消失。
`lib/html.ts` 的 `stripTags` 會認出「引號還沒收尾就遇到 `>`」的畸形標籤並把正文救回來。
全庫只有 1 檔、19 個這種標籤、86 個被夾住的漢字（連同後面接續的正文共救回 348 字）；
其餘 2182 檔的輸出與修正前逐位元相同。

## 永樂北藏

`bun run convert:ylbz` 產生 `ylbz/<經號>.txt`，同一經號的多卷合併成一檔，
檔內沿用 `^f<檔名>`（檔案）與 `^pg`（`<p>` 段落）標記。

與原 `gen.js` 有三處刻意的差別：

1. **走檔**：`nodebundle.filesFromPattern('**/*.htm')` 只匹配一層子目錄，4338 個 `.htm` 會漏掉 186 個較深層的檔案；改用 `walkFiles` 完整走到。
2. **分組**：`gen.js` 邊走邊依「經號有沒有變」輸出，同一經號若在走訪順序中分成好幾段，後面那一段會覆蓋前面的檔——全庫有 14 個經因此少掉內容（經 001 只剩 572/588 卷、經 068 只剩 1/12 卷）。現在先按經號收集再一次寫出，`verify:ylbz` 會檢查每檔的 `^f` 數等於來源卷數。
3. **解實體**：`&amp;` 會正確解成 `&`（原 `entity2unicode` 留著不動）；4338 檔只有 1 檔受影響。

## 折圖與文字鏈結

`ylz-image/<永樂北藏編號>-<卷號>.zip` 裡的 `001.jpg`、`002.jpg`… 是刻本的一折
（5 欄 × 17 字），一折正好對應純文字裡的 5 行。把那個對應關係寫進文字檔，
圖與文就接得起來。整條工具鏈在 `yblink/`，不依賴 bun，只用 Python。

### 一、檔名先統一成乾隆藏編號（`yblink/normalize.py`）

`qianlong-fixed/` 的檔名前綴有兩種來源，光看檔名分不出來：

| 例子 | 前綴其實是 |
| --- | --- |
| `001-16_1-19/1_1-200/220-001.txt` | **大正藏**經號 220 |
| `001-16_1-19/002/002-1.txt` | **乾隆藏**編號 2 |
| `024-28-83-108/083/278-01.txt` | **大正藏**經號 278（東晉本華嚴，60 卷） |
| `024-28-83-108/084/084-1.txt` | **乾隆藏**編號 84（唐實叉難陀本華嚴，80 卷） |
| `024-28-83-108/085/085-01.txt` | **乾隆藏**編號 85（唐般若本，40 卷） |

所以一律**讀檔案裡的卷首題**（前幾行裡第一個像「<經名>卷<數字>」的行），拿那個
經名去查 `乾隆藏.csv`，改寫成 `yb-txt/<乾隆藏編號>-<卷號>.txt`，不開次文件夾。
三個輔助線索用來解決同名異本（`乾隆藏.csv` 有 23 個經名對到多列）：

1. **檔名前綴**：它可能等於該經的乾隆藏編號，也可能等於大正藏編號。兩種數字的
   空間會撞在一起（大正 0278 是華嚴經，乾隆藏編號 0278 是另一部經），所以前綴
   候選只有在「經名像」或「譯者像」時才准進場。
2. **卷首題下一行的譯者**：跟 `乾隆藏.csv` 的「作譯者」模糊比對。譯者行只取
   卷首題**緊接在後**、長度 ≤ 20 字的行——正文一行是 17 字，不設限的話會把
   「…常勤積集出過」這種經文當成譯者行（集、注、述在經文裡到處都是）。
3. **卷號**：`乾隆藏.csv` 的卷數當上限，超過就重罰。

結果：`qianlong-fixed/` 2171 個 `.txt` → **1461 個**改名（775 個前綴本來是乾隆藏
編號、686 個是大正藏編號），710 個略過（序、目錄、品名索引——沒有卷首題，也沒有
對應折圖），**輸出檔名 0 個重複**。

### 二、^pg 標記（`yblink/mktxt.py`）

* `^pgNNN`（獨立一行）＝ 它下面那 5 行，對應 `<卷>.zip` 裡的 `NNN.jpg`。
* `^pgNNNa`、`^pgNNNb`…＝**沒有折圖**的正文：本卷的掃描缺葉，或那一葉被
  `yb-frame.py` 判成非正文而排除。字母跟著前一個有圖的 NNN，一塊最多 5 行。
* `^pg` 開頭的行只有標記，濾掉就還原成純文字，所以這步可以重複執行
  （已驗證：`0001-002`、`0001-006` 去標記後與 `qianlong-fixed` 原檔逐行相同）。

`0001-002` 的例子——中間那 15 行是第 28 葉（掃描判成非正文而排除），尾端 16 行是
第 35、36 葉：

```
^pg078
事可忍不衆生易度不持此蓮花以寄世尊
…（共 5 行）
^pg078a          ← 原書有、掃描沒有
…（5 行）
^pg078b
…（5 行）
^pg078c
…（5 行）
^pg079
坐爲諸菩薩說大般若波羅蜜多相應之法
…
```

### 三、對位用哪個 OCR（`yblink/link.py`）

整頁直接 OCR 不行（引擎會把相鄰欄混在一起），逐欄餵也不行；**把整折逆時針轉 90 度
再餵 PP-OCR** 才對：轉完 5 條直排欄變成 5 條橫排文字行，正好是 PP-OCR 的辨識模型
要的形狀。同一組折圖（`0001-002` 第 1–6 折，標準答案＝純文字非空行 #1..#30）：

| 方案 | 吐出幾行 | 字命中率 | 完全正確行 |
| --- | --- | --- | --- |
| Windows OCR 讀整張折圖 500×1105 | 23/30 | 0.076 | 0/30 |
| Windows OCR 讀五條直排欄 | 5/30 | 0.080 | 0/30 |
| RapidOCR 讀直排欄（未轉正） | 6/30 | 0.129 | 0/30 |
| **RapidOCR 讀轉正 90° 的整折** | **30/30** | **0.789** | 0/30 |

所以採用 RapidOCR（PP-OCR onnx，`rapidocr_onnxruntime`）+ 轉正。兩個實作細節：

* 關掉方向分類器（`use_cls=False`）：圖已經自己轉正了，cls 只是在猜 0/180 度，
  實測 1.41 s/折 → **0.84 s/折**。
* 比對前先做繁→簡（`zhconv`）：PP-OCR 的字典以簡體為主，純文字是繁體，
  不轉會系統性低估相似度（形近代換如 說→说、羅→罗 佔了很大一部分「錯誤」）。

### 四、對位演算法

折圖順序＝閱讀順序，所以「折圖 → 行號」是單調、幾乎線性的對應；唯一會跳的是
沒有折圖的那些葉。做法是 monotonic DP：

```
dp[i][j] = 對完前 i 行 OCR、前 j 行純文字的最高分
  對上          dp[i-1][j-1] + sim(ocr_i, ref_j)
  純文字多一行  dp[i][j-1]   - 0.08      ← 被排除的葉，很常見，罰小
  OCR 多一行    dp[i-1][j]   - 0.55      ← 辨識失敗，少見，罰大
```

相似度用 `rapidfuzz` 的整體比例（LCS）。結果（`yb-link/index.tsv`）：

| 卷 | 折圖 | 純文字非空行 | 對上的折圖 | 字命中率 | 沒有圖的行 |
| --- | --- | --- | --- | --- | --- |
| 0001-002 | 96 | 511 | 96/96（96 乾淨） | 0.79 | 31（第 28、35、36 葉） |
| 0001-006 | 54 | 488 | 54/54（52 乾淨） | 0.83 | 218（卷末 12 葉根本不在掃描裡） |

### 五、掃描本身不完整（重要）

`yonglebeizang/` 每一卷的頁數記在 `folio-map.tsv`。拿它跟純文字比對之後發現，
**很多卷的掃描只有該卷的一部分**：

| 卷 | 掃描頁數 | 純文字非空行 | 需要幾葉 | 折圖覆蓋 |
| --- | --- | --- | --- | --- |
| 0001-002 | 37 | 511 | ~34 | 480/511 = 94% |
| 0001-006 | 21 | 488 | ~33 | 270/488 = 55% |

`yb-out` 847 卷裡有 csv 的 845 卷，**717 卷有「沒有折圖的正文行」**，只有 1 卷是 0；
孤行數中位數在數十行，最多 238 行。也就是說「每五行一個標記就對得上」這條路在
這批資料上幾乎不成立——標記位置一定要靠 OCR 對位算出來，這也是 `^pgNNNa` 這種
後綴必須存在的原因。

### 六、OCR 校正對照表（`yblink/ocrtable.py`）

PP-OCR 的錯有很強的系統性：**「薩」最常被讀成「隆」**。所以「菩隆」這種詞在整部藏經裡
一次都不會出現，而校正表可以從對齊結果自動長出來：

1. 拿每一折的 `ref_text`（純文字）與 `ocr_text`（OCR），用編輯距離對齊，收集所有替換。
2. 每個替換連同**左右文脈**一起記（1、2、3 字）——`菩隆→菩薩` 是 2 字規則、
   `善隆摩→菩薩摩` 是 3 字規則。
3. 拿整部 `yb-txt` 當語料（1461 檔、1149 萬字）檢查候選的好字／壞字存不存在：
   壞的 n-gram 不在語料、好的在語料，才算數。
4. 過濾：1 字規則要次數 ≥ 10、精確率 ≥ 0.85；2／3 字規則要次數 ≥ 3、精確率 ≥ 0.90。

結果（`yb-link/ocr-fix.tsv`）：**1 字 172 條、2 字 2342 條、3 字 1763 條**。

| 最常見的 1 字 | 最常見的 2 字 | 最常見的 3 字 |
| --- | --- | --- |
| 隆→薩 2277 | 善隆→菩薩 1308 | 摩前隆→摩訶薩 648 |
| 无→無 733 | 前隆→訶薩 1306 | 善隆摩→菩薩摩 623 |
| 蓬→薩 604 | 隆摩→薩摩 1177 | 菩隆摩→菩薩摩 482 |
| 净→淨 600 | 菩隆→菩薩 515 | 增语是→增語是 210 |
| 真→眞 594 | 前谨→訶薩 486 | 波罹蜜→波羅蜜 170 |

（`无→無`、`缘→縁`、`静→靜`、`真→眞`、`语→語` 這些是簡→繁的系統性差異，
跟形近誤判同一張表一起處理。）

**留出法驗證**（一半的折建表、另一半只拿來量，避免自己考自己）：

| | 字集命中 | 1−正規化編輯距離 |
| --- | --- | --- |
| 校正前 | 0.775 | 0.719 |
| 校正後（訓練集） | 0.968 | 0.925 |
| **校正後（測試集）** | **0.962** | **0.915** |

也就是說 OCR 的字元準確率從 **72% 提到 91%**，而且不是過擬合。實例：

```
ref  逝世間解無上丈夫調御士天人師佛薄伽梵時現在彼安隱住持爲諸菩薩摩訶薩衆說大般若波羅蜜
ocr  逝世开解無上丈夫调御士天人師佛薄伽梵時现在被安住持萬諾善谨摩前懂泉就大般若波羅蜜
fix  逝世間解無上丈夫調御士天人師佛薄伽梵時現在彼安住持爲諸菩薩摩訶薩衆說大般若波羅蜜
```

原始 OCR 與 yb-txt 的符合率（1462 折、約 12 萬字）：

| 指標 | 原始字元 | 繁→簡後 |
| --- | --- | --- |
| 逐位符合（嚴） | 0.353 | 0.383 |
| 1−正規化編輯距離 | 0.721 | 0.780 |
| LCS 相似度 | 0.730 | 0.789 |
| 字集命中（寬） | 0.776 | 0.837 |
| 逐行 1−編輯距離（每行約 17 字） | 0.690 | 0.748 |

錯的型態（每 100 個純文字字）：**漏字 2.2、多字 0.1、形近替代 25.6**——
錯的幾乎全是「形近替代」，這正是校正表能救回 20 個百分點的原因。
逐位符合只有 0.35 是因為一個漏字或衍字會讓後面全部錯位，不是真的錯了 65%。

### 七、永樂北藏的 markdown（`yblink/ybmd.py`）

`lz-md/<編號>-<卷號>.md` 是龍藏的另一個來源（老載網站）：**有標點、繁體轉簡體、
段落軟折行**，所以它沒有刻本的分頁資訊。`yb-md/<編號>-<卷號>.md` 就是把永樂北藏的
折圖錨點疊回去——**每折文字起點加注 `^pgNNN`，編號就是 `yb-out/<卷>.zip` 裡的
`NNN.jpg`**，`^pgNNNa` 同樣是掃描沒有的葉。

做法（`yblink/ybmd.py`）：

1. `lz-md` 與 `yb-txt` 是同一段文字的不同來源：去標點、繁→簡之後，
   兩邊的 LCS 相似度 0.97~0.99、編輯距離只佔 1~3%（差的多是 lz-md 沒有的譯者行與卷末題）。
2. 把 yb-txt 的純文字接成長串 R 並記下每行起點；把 lz-md 去標點、繁→簡得到 M
   並記下每個字在檔案裡的絕對位置。
3. `editops(R, M)` 建出 R→M 的逐字對照（8600 字只要 0.01 秒、覆蓋 99.8%）。
4. 每一折（與每個無圖的塊）的第一行位置就換算成 md 的偏移，把 `^pg...` 插在那裡。
   若偏移正好落在一行的內容開頭（前面只有 `#` 與空白），標記自己佔一行，
   免得破壞 markdown 標題語法；其餘一律**行內插入**（因為 md 是軟折行，
   折與折的分界會落在句子中間）。

驗證（`yblink/mdverify.py`，124 卷、9570 個折錨點）：

| 項目 | 結果 |
| --- | --- |
| 錨點後面那段文字 vs 該折在 yb-txt 的頭 15 字，平均相似度 | **0.9979** |
| 相似度 ≥ 0.80 的比例 | **99.92%**（9562/9570） |
| 錨點位置非單調（順序錯）的卷 | 0 |
| 拿掉 `^pg` 是否逐位元還原成原 lz-md | 124/124 |

低於 0.80 的 8 個裡有 6 個是 `^pg001`：永樂北藏的卷首那折含「經題＋譯者」兩欄，
而 lz-md 沒有譯者行、卻多一個品名標題，所以是**版本結構差異**，不是放錯位置。
唯一放不出來的是 `0001-002` 的 `^pg096d`——那塊是卷末題（`大般若波羅蜜多經卷第二`），
lz-md 沒有這一行。

### 八、兩藏編號不同（`yblink/nummap.py`）

`yb-out/<卷>.zip` 的卷號是**永樂北藏**編號，`yb-txt/`、`lz-md/` 的檔名是**乾隆藏**編號，
兩者不必然相同：

| zip | 永樂北藏經名 | lz-md 檔 |
| --- | --- | --- |
| `1111-001.zip` | 四分律藏 | `lz-md/1112-001.md` |
| `1112-001.zip` | 根本說一切有部毗奈耶 | `lz-md/1113-001.md` |
| `1113-002.zip` | 摩訶僧祇律 | `lz-md/1114-002.md` |

`yb-link/number-map.tsv`（1619 筆，由 `normalize.py` 用經名＋卷數對出來）就是這張表。
`nummap.lz_key('1112-001')` → `'1113-001'`。**輸出檔名一律用永樂北藏編號**，
才會跟 zip 一致；文字來源才過這張表。

（0001–0xxx 那段兩藏編號剛好相同，所以早期不會發現；到 1112 就差了 1。）

### 八之一、二經同卷

`yonglebeizang/folio-map.tsv` 全藏 6770 筆裡有 **242 筆**是一個實體卷裝了兩部以上的經
（描述寫成 `①佛說法律三昧經一卷②佛說十善業道經一卷`）。這種卷的 zip 一個，
但文字要**依序接兩份（或三份）lz-md** 才對得上——否則 OCR 涵蓋兩部經、
文字只有一部，基底 LCS 會掉到 0.5 以下（`1094-001` 就是這樣被擋下來的）。

`nummap.md_src_list('1094-001')` → `['lz-md/1094-001.md', 'lz-md/1095-001.md']`；
`nummap.merge_md()` 只保留第一個檔的 YAML front matter，其餘取正文接起來。
接好之後 `1094-001` 的基底 LCS 由 <0.5 升到 **0.792**、逐行字數差 ≤1 佔 0.889。

### 九、用 OCR 的換行把龍藏 md 切成原書折行（`yblink/linebreaks.py`）

有些經 `qianlong-fixed` 根本沒收（例：1112-001 屬小乘律，不在 冊1-48+67 裡），
所以沒有「逐字正確又帶刻本換行」的純文字可用。這時改用：

* **字**：`lz-md/<乾隆藏編號>-<卷號>.md`（老載網站的龍藏，字對、有標點，但段落軟折行）。
* **換行**：折圖的 OCR。RapidOCR 的偵測框抓的是**原書真正的欄**，
  所以一行 OCR ＝ 刻本的一欄——字大約只對八成，但換行是對的。

做法是**單調分段 DP**：每一行 OCR 對到 md 的一段連續文字，分數＝那一段跟該行 OCR 的
相似度（減長度差懲罰），用 `editops` 的估計值開 ±26 字的窗口。
直接照 `editops` 把「OCR 行起點」換算成 md 位置會漂 1~3 個字
（例：`奉持得解脱　　毁` ＋ `破生恶趣`），DP 可以解掉大半。

還有一個坑：**最後一行不強制吃掉剩下的全部文字**。卷末那幾折 OCR 常常只抓到一兩行，
硬要那兩行涵蓋整卷剩下的幾百字，會把整段塞進一個「17 字的段落」
（實測 1112-043 的 `^pg098/099`）。現在讓它可以只吃跟自己差不多長的一段，
剩下的純文字留白（每字罰 0.02）。

**偈頌要用 md 自己的分句，不要用 OCR 的框**：龍藏 md 把偈頌排成「句　　句」一行兩句，
但刻本是一句一欄。卷首那幾頁 OCR 的欄偵測最不穩（一行抓成 4~15 字），照它切會變成

```
面满如初
日　　目净若青
莲
```

所以改成：**行內**的 `　　`（同一行、兩邊都是漢字的那種）一律當成刻本的欄界，
附近的 OCR 界直接吸附過去。散文裡沒有行內 `　　`（只有譯者行的行首縮排），所以不受影響。
修好之後同一段變成

```
稽首大悲尊　　
能哀愍一切

面满如初日　　
目净若青莲
```

（同一個位置有時會有兩個界被吸附到一起，插兩次會多一個空行，所以併界是必要的。）

`1112-001`（根本說一切有部毗奈耶卷第一，90 折、30 葉）的驗證：

| 項目 | 結果 |
| --- | --- |
| OCR 行數 | 457（90 折；捲末 1 折沒抓到字） |
| 插進 md 的 `^pg` | 89 |
| md 每一行 vs 該行 OCR 的**字數差 ≤1** | **86.7%**（≤2：91.9%） |
| 整折 100% 正確的折數 | **47 / 89** |
| 基底 LCS（OCR vs 龍藏，去標點繁簡後） | 0.711 |

也就是說**散文段落幾乎完全正確**（一折 5 行、每行 16–17 字，正好是刻本的欄），
驗證數字被兩處拖下來：

1. **卷首偈頌頁**（第 001–011 折）：那一頁是「很多短欄、每欄 5 字」的偈頌版式，
   但切圖時硬套了「5 欄 × 17 字」的模型，所以 RapidOCR 的欄偵測不穩
   （一折抓到 5~10 行，每行 2~15 字）。
2. **卷末 3 折**（085、086、089）：OCR 只抓到 2 行。

逐折細節在 `yb-link/1112-001.linecheck.json`。

### 九之一、驗證新切圖（`--imgs`）

切圖那條線在做品質修正時，會把單卷試切到目錄（例：`_t1112_018_out/001.jpg`…）。
這種目錄沒有 zip 也沒有 CSV，但 md 這條路只需要「折圖順序」＋「每一折的行」，
所以可以直接吃：

```
python yblink/linebreaks.py --vol=1112-018 --imgs=_t1112_018_out --json=<報告>
```

實測（`len_ok1` ＝ md 每一行的字數與該行 OCR 差 ≤1 的比例）：

| 卷 | 折 | OCR 行 | ±1 字 | ±2 字 | 基底 LCS |
| --- | --- | --- | --- | --- | --- |
| 1094-001（二經同卷） | 66 | 326 | 0.871 | 0.923 | 0.793 |
| 1112-043 | 99 | 495 | **0.921** | 0.972 | 0.760 |

1112-043 加「卷末尾段」修正前是 0.907，修正後 0.921。
另外三卷（1112-018／1112-045／1116-011）修正前量到 0.848／0.877／0.899；
那幾個測試目錄已被切圖那條線清掉，要用新切圖重跑才會有新數字。

舊切圖的 16 卷（`yb-out-prefix`）也在同一個範圍：±1 字 0.823 ~ 0.927。
兩批的準確度差不多，所以**換切圖不會讓 md 這條線失效**，重跑即可。

`--imgs` 直接吃折圖目錄，所以不需要 zip 也不需要 CSV
（md 這條路只需要「折圖順序」＋「每一折的行」）；`--imgs` 走的是
`rapid.ocr_array`（直接把 numpy 陣列餵給引擎，不落地成 PNG），
比 `ocr_file` 少一次編碼，實測同一卷多抓到 13 行、±1 字多 1.4 個百分點。

### 九之二、品管（`yblink/qc.py` → `yb-link/qc.tsv`）

每一卷的 md 逐項檢查：

| 欄 | 意思 |
| --- | --- |
| `method` | `model`（算術模型）／`dp`（逐折 OCR＋DP）／`linebreaks`（龍藏字＋OCR 換行） |
| `folds` / `anchors` / `no_image` | 折數、`^pgNNN` 錨點數、`^pgNNNa` 無圖錨點數 |
| `quality` | linebreaks 用「逐行字數差 ≤1 的比例」；model/dp 用字命中率 |
| **`intact`** | **把 md 的標記與空白全部拿掉，是否逐字等於來源正文** |
| `ok` / `why` | 通過與否、不通過的原因 |

`intact` 是最強的一條：只要它成立，就代表這份 md **一個字都沒有被吃掉或重複**，
換行只是插入換行、錨點只是插入標記。153 卷全部 `intact=1`。

`^pg` 的標記形式有兩種要一起認：`^pgNNN`（折圖）、`^pgNNNa`（無圖的葉）；
同一葉孤行超過 26 塊時還會接後綴（`^pg054a_2`、`^pg054b_2`…，見 `mktxt.suffix()`）。
品管第一次跑就是漏認了這個後綴，把 153 卷全部誤判成「正文不一致」（md 恰好多出 18×2 個字）。

### 九之三、每張折圖對應到 md 的哪幾行（`yblink/mdindex.py`）

`yb-link/<卷>.tsv` 是「折圖 → **純文字**（yb-txt）行號」，只有走 model／dp 那條路的卷才有，
而且基準是 yb-txt 的行。linebreaks 那條路（沒有純文字可對的卷）基準是龍藏 md，
沒有那種行號，所以另外產生一份用 **md 自己的行號**當基準的表：

```
yb-link/md-index.tsv
vol  fold  kind  sub  line_first  line_last  lines  char_first  char_last  chars  head
```

`line_first`／`line_last`＝這一折的文字在 `yb-md/<卷>.md` 裡是第幾行到第幾行（1 起算，
含 `^pgNNN` 那一行）；`char_first`／`char_last`＝字元位移；`head`＝開頭 16 個字（去掉標記與空白），
可以直接肉眼核對。`kind` 空的是一般折圖，有字母（`a`、`b`…）的是沒有對應折圖的文字塊。

以 `1112-001` 為例：

| fold | line_first | line_last | chars | head |
| --- | --- | --- | --- | --- |
| 001 | 10 | 22 | 72 | `#根本说一切有部毗奈耶卷第一##` |
| 002 | 23 | 46 | 126 | `弟子众调伏调伏除众过敬礼法中尊佛` |
| 003 | 47 | 69 | 118 | `独觉身心静及以阿罗汉咸由律行成三` |

153 卷共 **12240 折 + 1856 塊無圖文字**。批次每跑完一輪會自動重寫。

### 九之四、用眼睛核對（`yblink/preview.py`）

產一頁 HTML：左邊是折圖（直接從 `yb-out/<卷>.zip` 讀出來、base64 內嵌，單一檔案帶著走），
右邊是這一折在 md 裡的文字。

```
python yblink/preview.py --vol=1112-001 --out=_v9/1112-001.html
```

注意頁尾的註記會隨方法不同：

* `linebreaks` 那條路（龍藏字＋OCR 換行）——右邊**一行就是刻本一欄**，可以直接對欄。
* `model`／`dp` 那條路——md 的行是龍藏原本的**軟折行**，只有 `^pg` 的位置是準的，
  不要拿行來對欄。

（`1112-001` 5.9 MB／86 折、`1112-043` 6.8 MB／99 折、`0001-002` 7.3 MB／102 折。）

### 十、怎麼跑

```
python yblink/normalize.py            # qianlong-fixed → yb-txt + yb-link/number-map.tsv
python yblink/batch.py --jobs=6       # 每卷：轉正 → OCR → 對位 → 寫 ^pg 標記 ＋ yb-md（可續跑）
python yblink/ybmd.py --all --verify  # 只重做 yb-md（已有 yb-link 的卷）
python yblink/mdverify.py             # 獨立驗證 yb-md 的錨點位置
python yblink/linebreaks.py --vol=1112-001 --ocr=<OCR目錄> --json=<報告>   # 沒有純文字時走這條
python yblink/coverage.py             # 每卷「純文字行數 vs 折圖數」的孤行統計
python yblink/bench.py                # 四種 OCR 餵法的比較
python yblink/accuracy.py             # OCR vs yb-txt 的符合率（校正前後各一份）
python yblink/ocrtable.py --build     # 建 OCR 校正對照表
python yblink/ocrtable.py --validate  # 留出法驗證校正表
python yblink/verify_txt.py           # 檢查 yb-txt 命名／卷首題／缺號
python yblink/model.py                # 用「每葉 15 欄」的算術模型檢查 OCR+DP 的答案
python yblink/summary.py              # 重建 yb-link/index.tsv
```

`batch.py` 會自己判斷一卷走哪條路：

| 情況 | 走法 | 成本 |
| --- | --- | --- |
| `yb-txt/<乾隆藏編號>.txt` 存在（有逐字正確的純文字） | `fast.py` 算術模型＋6 個 OCR 錨點 → `yb-link` → `mktxt` 寫 `^pg` → `ybmd` 疊 md | 一卷約 8 秒 |
| 算術模型不成立（版式不是 15 欄 × 17 字） | 逐折 OCR ＋ DP 對位 | 一卷約 100 秒 |
| **沒有純文字**（例：1112-001，qianlong-fixed 沒收） | 全部折圖 OCR → `linebreaks.py`（龍藏的字＋OCR 的換行） | 一卷約 65 秒 |

**錨點分數取中位數，不要取平均**：錨點是「第一個有折圖的頁、1/4、1/2、3/4、倒數第二頁、最後一折」
共 6 折。只要有一個落在糊掉或破損的折上，平均就會被拉下來——實測 `0001-014`
四個錨點裡有一個只有 0.503，平均 0.669（離門檻 0.55 很近，會誤判成「模型不成立」而掉進
慢 16 倍的 DP 路），改成 6 個錨點取中位數後是 **0.94**。多兩次 OCR（約 2 秒）換來的穩定度很划算。

（舊的 0001-* 那批切圖有 17 卷就是這樣掉進 DP 的；用目前的 `yb-frame.py` 重切之後，
`0001-014`、`0001-061` 都能走模型，offset 也對。）

資料夾位置都不寫死在程式裡，用環境變數覆蓋（見 `yblink/paths.py`）：
`YB_ZIP_DIR`（預設 `ylz-image`）、`YB_CSV_DIR`（`ylz-crop-pos`）、`YB_TXT_DIR`（`yb-txt`）、
`YB_LINK_DIR`（`yb-link`）、`YB_MD_DIR`（`lz-md`）、`YB_OUT_MD`（`yb-md`）。
`batch.py` 的 `--out`／`--csv-dir` 會寫進這些變數，子行程也吃得到。
（`ylz-image/` 早期是 `yb-out-prefix`／`yb-csv-prefix` 的複本，那兩個目錄保留為來源備份。）

`batch.py` 預設 `--mode=auto`：先用 `fast.py` 的**算術模型 + 4 個 OCR 錨點**
（一卷 4 次 OCR，約 6 秒）定出 offset，模型不成立才退回逐折 OCR + DP
（一卷 80 次 OCR，約 100 秒）。`--mode=full` 一律走逐折 OCR。

單卷除錯：

```
python yblink/prep.py 0001-002 --out=_scratch/ocr --variants=rot90
python yblink/rapid.py _scratch/ocr/0001-002/rot90 _scratch/ocr/0001-002/ocr --pattern=*.png
python yblink/link.py --vol=0001-002 --ocr=_scratch/ocr/0001-002/ocr \
    --ref=yb-txt/0001-002.txt --out=yb-link
python yblink/mktxt.py --vol=0001-002                      # yb-txt 的 ^pg 標記
python yblink/ybmd.py --vol=0001-002 --verify              # yb-md 的錨點
```

`yb-link/<卷>.tsv` 是逐折的對照表（`fold, page, fold_in_page, n_ocr, n_hit,
line_first, line_last, idx_first, idx_last, contiguous, conf, ref_text, ocr_text,
ocr_fixed`），`yb-link/<卷>.json` 是同一份加統計，`yb-link/index.tsv` 是彙總，
`yb-link/normalize.tsv` 是改名對照表，`yb-link/number-map.tsv` 是兩藏編號對照表。
